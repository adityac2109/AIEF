# BearingGuard: evaluating vibration anomaly detectors and calibrated alarms on IMS run-to-failure data

## Abstract

We evaluate time-domain and envelope-spectrum features with z-score and Isolation
Forest detectors for flagging rolling-element bearing degradation on the NASA
IMS run-to-failure data. Every bearing is calibrated on its own early life,
alarms need persistence, and IMS test 3 was sealed until the protocol was frozen
and tagged. On development tests 1–2 (3 failures, 5 non-failed bearings), no
detector dominates. Rig restarts produced simultaneous level shifts that inflated
a naive baseline's lead times, and restart re-centering removed most of those
alarms but can mask a failure. Empirical p-value thresholds behaved close to
nominal right after calibration but exceeded α by 3.6–5.7× over whole runs. On
the holdout, test 3 showed no feature-level degradation of the failed bearing
before the readme's documented end time, so no detector meaningfully detected
it within the documented range. In the 13 undocumented days that follow, all
four bearings degrade together. We report these as case studies; four failures
cannot support significance claims.

## 1. Motivation

Condition monitoring aims to warn of bearing damage early enough to plan
maintenance while keeping false alarms tolerable. Published results on the IMS
data often use random splits of correlated snapshots, tune thresholds on the
same runs they report, or show lead times without checking what triggered the
alarms. This project asks how much of the apparent performance survives an
evaluation designed to prevent those problems.

## 2. Related work

- **Envelope analysis.** Randall and Antoni's tutorial (*Mechanical Systems and
  Signal Processing* 25 (2011) 485–520) gives the standard bearing kinematics
  and the band-pass + Hilbert envelope method used for our spectral features.
- **IMS dataset.** It was generated by the IMS center with Rexnord. The readme
  cites Qiu, Lee, Lin, *Journal of Sound and Vibration* 289 (2006) 1066–1090.
  Bearing geometry (16 rollers per row, 0.331 in rollers, 2.815 in pitch
  diameter, 15.17°) is as compiled in a public dataset summary
  ([hustcxl/Rotating-machine-fault-data-set](https://github.com/hustcxl/Rotating-machine-fault-data-set/blob/master/doc/IMS.md)).
  We could not access the original paper to confirm it.
- **Isolation Forest.** F. T. Liu, K. M. Ting, Z.-H. Zhou, "Isolation forest,"
  IEEE ICDM 2008, pp. 413–422.
- **Conformal anomaly detection.** Leave-one-out, bootstrap and cross-conformal
  anomaly detectors, which extend split (inductive) conformal anomaly detection,
  are defined and evaluated in [arXiv:2402.16388](https://arxiv.org/abs/2402.16388).
  The validity of all of these rests on exchangeability. Conformal calibration has
  also been applied to bearing RUL intervals
  ([PHME paper](https://papers.phmsociety.org/index.php/phme/article/view/4902)).
- **Linear RUL labels on IMS.** A recent preprint whose title reports that
  linear RUL labels disagree with vibration degradation on XJTU-SY and IMS
  ([arXiv:2607.28115](https://arxiv.org/pdf/2607.28115)). Only its title and
  abstract-level summary were reviewed here.

**What differs here.** We claim no new detector. The contribution is an
evaluation: a frozen, tagged protocol with a sealed holdout; restart handling
measured as its own factor; and an empirical check of whether calibration
p-values keep their nominal false-alarm rate on drifting run-to-failure data.
We did not run a systematic literature search, so we do not claim this
combination is new.

## 3. Research question and hypotheses

*How reliably can vibration-based ML methods detect bearing degradation under
realistic evaluation conditions, and can uncertainty-aware alerting improve the
trade-off between missed failures and false alarms?*

- **H1.** More complex models do not consistently outperform simple baselines.
- **H2.** Performance drops on an unseen run. IMS has one operating condition,
  so "unseen condition" cannot be tested.
- **H3.** Uncertainty-aware alerting can improve a maintenance-relevant trade-off
  but may increase missed detections or delay alerts.

## 4. Data

Three run-to-failure tests on one rig: 2000 RPM, 6000 lb radial load, four
Rexnord ZA-2115 bearings. Each file is a 1 s snapshot at 20 kHz, recorded about
every 10 minutes. Failures are documented only as the state at the end of each
test: T1B3 inner race and T1B4 roller element, T2B1 outer race, T3B3 outer race.
Measurement units are not documented.

Validation (`data/README.md`) found:
- three dead-signal files (two at the end of test 2, the last file of test 3),
  which were excluded and listed;
- 145 five-minute intervals in test 1 where the readme mentions 43, and 21 gaps
  over 1 h;
- 6,324 test 3 files where the readme documents 4,448. The extra 1,876 files run
  13 days past the documented end.

## 5. Method

**Features** (per snapshot, one channel per bearing):
- RMS, kurtosis and crest factor;
- envelope SNR at BPFO, BPFI and BSF: 1–9 kHz Butterworth band-pass, Hilbert
  envelope, sum of the peaks at harmonics 1–3 within ±2%, divided by the median
  envelope level in 10–500 Hz. Defect frequencies are computed from the geometry
  (236.4 / 296.9 / 139.9 Hz).

A high-frequency energy ratio was computed, then dropped: it fell rather than
rose with damage.

**Calibration.** Each bearing uses its first 144 usable snapshots and they are
never scored. For Isolation Forest, rows 1–96 are fit rows and rows 97–144 give
held-out calibration scores. After a shutdown of 8 h or more, the features are
re-centered on the mean of the next 18 snapshots, which are left unscored.

**Detectors.**
- z-score on each feature, alarm if any z > k;
- Isolation Forest (200 trees, 5 seeds) with either a k·σ threshold on the
  held-out calibration scores, or an empirical p-value p = (1 + #{cal ≥ s})/(n + 1)
  with alarm when p ≤ α.

The p-value controls the per-snapshot false-exceedance rate at α only if new
scores are exchangeable with the calibration scores.

**Alarm.** At least 3 exceedances in the last 5 snapshots.

**Metrics.**
- First-alarm lead time, in operating hours;
- *detected*: in alarm during the failed bearing's last 24 operating hours;
- alarm episodes per 100 monitored hours and time in alarm on non-failed bearings;
- alarm episodes on failed bearings starting in the first half of monitored time;
- blind time;
- restart-triggered episodes;
- observed vs nominal per-snapshot exceedance rate for p-value thresholds.

## 6. Protocol

- Development on tests 1–2. Primary settings (k = 3, α = 0.05, seed 0) were
  declared before the development run, and grids k ∈ {3, 4, 5, 6} and
  α ∈ {0.1, 0.05, 1/49} are reported in full.
- All seven methods were carried to the holdout; none was selected using
  development data.
- Test 3 was sealed in code. The holdout ran once at tag `protocol-v1-frozen`
  (`9e61758`) under a pre-registered range decision:
  - primary: the documented range;
  - secondary: the full archive.

  The decision used only filenames, timestamps and the readme.
- The z-score methods in the new runner reproduce the earlier baseline and
  calibration-study results exactly, which checks the implementation for
  consistency.

## 7. Results

### 7.1 Restart shifts (tests 1–2)

After a 148 h shutdown, RMS rose on every test 1 bearing at once: +14.2% to
+21.6%, up to 37σ above calibration. In the naive baseline this produced
300 h+ lead times and 53.7% of non-failed time in alarm. Re-centering after 8 h+
shutdowns:
- cut restart-triggered alarm episodes from 14 to 4;
- cut non-failed time in alarm to 18.0%;
- cost 8.9% blind time on test 1.

Re-centering after every 1 h gap left the RMS detector silent on failed T1B4.
Cross-bearing log-ratio normalization did not cancel the shift, because the
shift differed between bearings; restart-triggered alarm episodes rose from 14
to 38. Details: `results/calibration_study.md`.

### 7.2 Detector comparison (tests 1–2, primary settings)

| Method | Detected | Lead h (T1B3/T1B4/T2B1) | Early-half eps, failed | Non-failed eps/100 h | Non-failed time in alarm |
|---|---|---|---|---|---|
| zscore_time_raw | 3/3 | 321 / 308 / 74 | 1 / 19 / 1 | 1.13 | 53.7% |
| zscore_time | 2/3 | 215 / 103 / 74 | 2 / 0 / 1 | 1.97 | 18.0% |
| zscore_time_env | 3/3 | 227 / 297 / 74 | 3 / 17 / 1 | 2.16 | 18.2% |
| iforest_time | 3/3 | 227 / 278 / 55 | 11 / 4 / 0 | 6.95 | 13.2% |
| iforest_time_env | 3/3 | 215 / 298 / 54 | 3 / 27 / 0 | 3.47 | 3.9% |
| iforest_time_pvalue | 3/3 | 288 / 278 / 74 | 26 / 9 / 1 | 11.45 | 26.2% |
| iforest_time_env_pvalue | 3/3 | 279 / 310 / 63 | 21 / 33 / 0 | 10.14 | 12.3% |

Across 5 Isolation Forest seeds every method still detects 3/3. The non-failed
alarm rate varies by up to 1.5×.

### 7.3 Calibration p-values

On non-failed bearings, at α = 0.05, the observed per-snapshot exceedance rate is:

| Variant | First 48 scored snapshots | First half of run | Whole run |
|---|---|---|---|
| Time + envelope | 0.033 | 0.095 | 0.179 |
| Time only | 0.067 | 0.176 | 0.285 |

At α = 0.05 the p-value variant produced 10.14 non-failed alarm episodes per
100 h, against 3.47 for k = 3 on the same score. Both detected 3/3.

### 7.4 Holdout (test 3)

**Primary, documented range.**
- No method detects T3B3 in a meaningful way. The single method that counts as
  "detected" (`iforest_time_env_pvalue`) alarms from the first hours of the run.
- Before the documented end, T3B3's RMS is at its calibration level (z = 0.4)
  and its BPFO SNR is 5.9 against 5.5.

**Secondary, full archive.**
- All four bearings degrade together in the final ~60 operating hours.
- The z-score methods detect T3B3 59 h before the end of the archive but also
  alarm on all three non-failed bearings.
- `iforest_time` detects T3B3 58 h before the end with no non-failed alarms; it
  is a single case.

Details: `results/holdout_results.md`.

## 8. Error analysis

- **Masking by re-centering (T1B4, `zscore_time`).** The alarm stops near
  operating hour 290. The restart at hour 338 re-baselines the elevated level, so
  the bearing is not in alarm at the end (`alarm_raster_test1.png`).
- **Defect-band mismatch (T1B4).** The documented roller failure shows no clear
  rise in the BSF band. The BPFO band rises sharply at the end instead
  (`envelope_failed.png`).
- **Isolation Forest saturation.** Beyond the training range, scores barely grow
  with how far a point lies, so k·σ thresholds on the score spread are coarse:
  at k = 6, `iforest_time_env` misses T2B1.
- **Rig-wide events.** The test 1 restart shift and the test 3 end-of-archive
  degradation both appear on every bearing. Per-bearing detectors cannot tell
  which bearing is the cause.
- **Label–data mismatch (test 3).** The documented failure time precedes any
  visible degradation by about 11 days of recorded data.

## 9. Discussion

- **H1: supported, descriptively.** Isolation Forest and envelope features
  change *which* errors occur rather than removing them. On the development
  data, the simplest re-centered z-score had the fewest early alarms but missed
  a failure.
- **H2: cannot be cleanly assessed.** The holdout's documented label does not
  match its data, so poor primary-analysis detection is not evidence of poor
  generalization. One operating condition prevents any condition-shift test.
- **H3: not supported in this form.** Calibration p-values gave interpretable
  thresholds but no reliable false-alarm guarantee on drifting data. They raised
  more false alarms than k·σ at equal detection.
- **Practical implications.** Restarts and rig-wide changes must be modelled
  explicitly. Any alarm system on such data needs a way to tell machine-wide
  events from bearing-specific ones. Reported lead times mean little unless the
  alarms behind them are inspected.

## 10. Threats to validity

- Very few failures (4) and no fault-onset ground truth; the proxy labels count
  cross-talk and aged non-failed bearings as false alarms.
- Development choices (8 h restart rule, dropped high-frequency energy ratio)
  were informed by tests 1–2. Test 3 had no shutdown of 8 h or more, so the
  restart rule was not exercised on the holdout.
- The test 3 documented range may not correspond to the failure, which weakens
  the primary holdout analysis.
- One channel per bearing; test 1's other axis was not examined.
- The secondary holdout run's metadata records `git_dirty: true` because of
  untracked report files the runner itself wrote. Code was unchanged (see the
  deviations section of the holdout results).

## 11. Limitations and future work

- **Not done:** remaining-useful-life estimation (labels unsupported), deep
  models (not justified by 4 failures), per-bearing band selection (kurtogram),
  multi-channel fusion, and a dashboard or API.
- **Future work:**
  - repeat the protocol on a run-to-failure dataset with more failures and
    several operating conditions (for example XJTU-SY or PRONOSTIA), under a new
    pre-registered protocol;
  - detect rig-wide common-mode events explicitly before alarming per bearing;
  - try time-adaptive calibration (rolling or weighted conformal methods) that
    does not assume exchangeability with the first day.

## 12. Reproduction

See the README and `experiment_protocol.md`. In short:

```bash
pip install -r requirements-lock.txt && pip install -e ".[dev]" && pytest
python -m bearingguard.data.download
python -m bearingguard.data.validate --test 1 2
python -m bearingguard.features.build --test 1 2 --set time spectral
python -m bearingguard.experiments.detect configs/protocol_v1.toml
python -m bearingguard.reporting.report runs/protocol_v1_dev --out docs/results/protocol_v1_dev
```
